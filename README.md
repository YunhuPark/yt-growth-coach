# YT Growth Coach (화면 이름: ClipLab)

유튜브 크리에이터를 위한 **AI 영상 편집 도우미**(쇼츠 구간 뽑기, 한 편 자동 편집, 무음·군말 자르기, 가로→세로 자동 프레임, 전환·효과음, 박자에 맞춰 효과 넣기, 시청 지속 분석, 영상 주소 분석)와, 내 채널 지표와 트렌드로 **다음에 무엇을 만들지** 추천하고 성과를 검증하는 **채널 대시보드**를 한 저장소에 담은 로컬 우선 웹 앱입니다. 영상은 내 컴퓨터에서 처리되고, AI 기능은 내 API 키로만 호출합니다.

- **바로 실행**: `docker build -t cliplab .` 후 `docker run --rm -p 3000:3000 -v cliplab-data:/app/.data cliplab` → http://localhost:3000 (자세한 것은 "실행·배포"). Docker 없이는 아래 "실행"의 `npm run dev`.
- **공개 데모**(브라우저에서만 도는 시청 지속 분석과 소개 페이지): 배포 방법은 "실행·배포"에 있고, 아직 배포 전이라 주소는 없습니다.
- **구조와 규칙**: "코드 구조"(편집기·채널·공통의 경계를 린트가 지킴), `DESIGN.md`(화면 규칙).

## 화면 구성과 두 가지 사용 방법

`/`는 소개 페이지(기능·사용 방법·안심 포인트), `/edit`는 영상 편집 도우미, `/channel`은 채널 대시보드입니다. 디자인 규칙(색·글꼴·모양, 하지 말아야 할 것)은 `DESIGN.md`에 정리되어 있습니다. 브랜드 이름은 화면에서 **ClipLab**으로 보이며(`src/components/site/Brand`의 `BRAND` 한 곳에서 바꿈), 저장소 이름은 그대로입니다.

| | 영상 편집 도우미 (`/edit`) | 채널 대시보드 (`/channel`) |
|---|---|---|
| Google 로그인 | **필요 없음** | 필요 (채널 분석·성과 추적) |
| 하는 일 | 영상을 고르면 쇼츠 구간 뽑기, 한 편 자동 편집(컷·자막·제목·설명), **무음·군말 자동 컷**, **자동 프레임(가로→세로, 따라가며 자르기)**, **전환·효과음 자동 삽입**, **박자에 맞춰 효과 넣기**, **시청 지속 분석**, 영상 주소 분석, 영상 만들기 | 내 채널 진단, 트렌드, AI 추천, 제작 패키지, 성과 추적, 원가 측정 |
| 필요한 것 | 영상 처리 도구(ffmpeg, 설치하면 함께 들어옴)와 한글 글꼴. AI를 쓰는 작업에만 `ANTHROPIC_API_KEY`(YouTube 주소 분석의 댓글 읽기는 `YOUTUBE_API_KEY`, 선택). 무음 컷·자동 프레임·전환·효과음·박자 효과·시청 지속 분석은 AI 키 없이 됩니다 | 위 + Google Cloud 설정 |

**영상 편집 도우미**는 한 화면에 하나씩, 버튼으로 넘어가는 네 단계입니다: ① 하고 싶은 **작업 고르기** → ② 편집할 **영상 올리기**(파일을 끌어다 놓거나 경로 입력, 사용 권한 확인을 한 번만) → ③ **꾸미기**(자막 스타일·세로 화면·전환·효과음, 전부 선택 사항) → ④ AI 제안을 확인하고 **만들기**. "유튜브 주소로 분석"은 영상 파일이 필요 없어 ①→④ 두 단계로 끝납니다. 위쪽 단계 표시에서 지나온 단계를 눌러 되돌아갈 수 있고, 되돌아가도 입력한 값과 찾은 결과는 남습니다. 로그인이 없으면 "내 채널에서 잘된 쇼츠 길이 반영" 같은 채널 기반 보정만 빠지고 나머지는 똑같이 동작합니다.

화면 맨 위의 **준비 상태**가 영상 처리 엔진, 한글 폰트, AI 키, YouTube 키, 음성 인식 모델, Google 연결 여부를 확인해 빠진 것과 해결 방법을 알려 줍니다(키 값은 표시하지 않고 설정 여부만 확인). 필수 항목(처리 엔진·폰트·AI 키)이 없으면 빨간 안내가 먼저 뜹니다.

## 채널 대시보드 기능

영상 편집 도우미의 기능은 아래 각 절("무음·군말 자동 컷", "자동 프레임", "전환·효과음", "박자에 맞춰 효과 넣기", "시청 지속 분석", "AI 자동 편집" 등)에 있고, 이 표는 `/channel`의 탭입니다.

| 탭 | 내용 |
|---|---|
| 내 채널 진단 | 영상별 품질 점수(조회 속도·시청 지속률·참여·구독 전환 CVR), CTA 반응률, 자동 회고, 제목·길이·요일 패턴. 점수·총 조회수·구독 전환순 정렬 |
| 트렌드 | 국가/카테고리별 인기 급상승, 경쟁 채널의 "평소 대비 터진 영상", 키워드별 상위 영상. **비슷한 채널 찾기**: 내 영상의 제목·해시태그로 채널을 파악하고, 후보 채널의 최근 영상 30개를 직접 확인해 같은 소재를 꾸준히 다루는 채널만 남김(해시태그만 끼운 채널은 제외하고 이유 표시) |
| AI 추천 | **원클릭 준비**: 버튼 하나로 채널 데이터·트렌드 갱신 → AI 추천 → 상위 1~3개 아이디어의 제작 패키지 → 1순위 아이디어의 소재 후보까지 이어서 실행(진행 단계 표시, 끝나면 알림). **주간 자동 실행**도 같은 카드에서 요일·시간을 정해 켤 수 있음. 한 줄 결론, 핵심 지표, 우선순위별 할 일, 영상 아이디어 6~8개. 결과는 저장됨. 아이디어마다 **제작 패키지** 생성. 쇼츠·릴스는 제목 3안, 훅 자막, 컷 구성, 엔딩 CTA, 고정 댓글, 설명, 해시태그, 업로드 시간, 확인할 빈칸. **롱폼**은 여기에 썸네일 문구 안, 오프닝 대본, 챕터(시간 포함), 이탈 방지 장치, 중간·엔딩 CTA가 붙고 설명에 챕터 목록이 자동으로 들어감 |
| 영상 제작 | **A. 소재 후보 찾기**: 아이디어에 맞는 원본 영상을 링크·타임스탬프·시청자 댓글 시간대로 안내(내려받지 않음, 공식/팬 편집본 추정 표시). **B. 편집 자동화**: 내가 권리를 가진 영상 파일에 훅 자막, 구간 자막(롱폼은 챕터 제목 카드), 엔딩 카드를 입혀 mp4 생성. 쇼츠·릴스는 1080×1920 세로(3분 이하), **롱폼은 1920×1080 가로**(최대 4시간). 렌더링은 백그라운드로 진행되며 진행률이 표시되고, 큰 파일은 업로드 대신 **이 컴퓨터의 파일 경로**를 입력할 수 있음 |
| 영상 제작 · C | **C. AI 자동 편집**: 영상 파일을 AI가 훑어보고(대표 장면 이미지, 장면 전환, 무음 구간, 초당 소리 크기) **버릴 부분을 컷하고, 훅·구간 자막과 제목 후보 3개·설명·해시태그를 제안**. 먼저 계획을 보여 주고 확인한 뒤 "이 계획으로 영상 만들기"로 렌더링(컷한 구간을 이어 붙이고 자막 시간도 편집 후 기준으로 자동 변환). **음성 인식**을 켜면 이 컴퓨터에서 대사를 글자로 바꿔(Whisper) 대사 자막과 문장 단위 컷에 반영 |
| 영상 제작 · E | **E. 영상 주소로 분석 (파일 없이)**: 유튜브 영상 주소를 붙이면 AI가 **영상 요약, 내 채널용 주제 3~5개, 제목 5개, 쇼츠 구간 후보**(점수·이유·훅·제목·**편집 지시서**), **롱폼 구성안**(구간·챕터·제목·설명)을 만듦. 영상을 내려받거나 복사하지 않고 공개된 제목·설명·챕터·댓글과 YouTube가 제공하는 미리보기 이미지 4장을 근거로 함 |
| 영상 제작 · D | **D. 긴 영상에서 쇼츠 뽑기**: 긴 영상 하나를 넣으면 AI가 쇼츠로 올리기 좋은 구간을 **점수·이유·훅·제목과 함께 최대 6개 후보**로 제안. 후보별로 **구간 미리 보기**(낮은 화질 복사본)와 **자막 편집**(음성 인식 오타 수정·추가·삭제)을 한 뒤 "쇼츠 만들기"(또는 모두 만들기)를 누르면 훅 자막과 대사 자막이 붙은 1080×1920 쇼츠가 렌더링됨. 옵션으로 같은 영상의 **롱폼 요약 구성**(컷·챕터·제목·설명, 1920×1080)도 함께 제안 |
| 성과 추적 · AI 점수 검증 | 쇼츠 뽑기로 만든 쇼츠를 실제로 올린 영상에 연결하면, AI가 준 점수가 실제 성과(업로드 7일 후 품질 점수)와 맞았는지 **순위 상관(Spearman)**으로 보여 줌 |
| 성과 추적 | 기존 영상의 첫 1·3·7·28일 성적으로 **쇼츠와 롱폼을 따로** 기준선을 만들고, 새로 올린 영상을 "상위 몇 %"로 비교. 시도한 요소(시리즈 태그, 엔딩 CTA 등)별 효과를 모아 다음 AI 추천에 반영. **자동 수집**: 새 영상을 감지해 추적을 시작하고, 1·3·7·28일차 결과가 확정되면 그 값을 기록하며 알림을 남김 |

## 실행

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run dev                  # http://localhost:3000
```

> OAuth 로그인은 앱 내장 브라우저에서 막히는 경우가 있어 **Chrome/Edge에서 `localhost:3000`** 으로 진행하세요.

### Google Cloud 설정 (최초 1회)

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트 생성(또는 기존 프로젝트 사용)
2. **API 및 서비스 → 라이브러리**에서 `YouTube Data API v3`, `YouTube Analytics API` 사용 설정
3. **Google 인증 플랫폼**: 사용자 유형 외부(테스트 중), **테스트 사용자에 내 구글 계정 추가**
4. **클라이언트 → OAuth 클라이언트 ID(웹 애플리케이션)**, 승인된 리디렉션 URI: `http://localhost:3000/api/auth/callback`
5. 클라이언트 ID/보안 비밀번호 → `.env.local`의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` (보안 비밀번호는 생성 직후에만 볼 수 있음)
6. **API 키**(영상 제작 탭의 댓글 기반 장면 힌트에 필요): 사용자 인증 정보 → API 키 만들기, **YouTube Data API v3로 제한** → `YOUTUBE_API_KEY`
7. `ANTHROPIC_API_KEY` 입력 (AI 기능용)

테스트 모드에서는 refresh token이 7일 뒤 만료되므로 그때마다 다시 연결해야 합니다.

## 무음·군말 자동 컷

말하는 영상에서 **말이 끊긴 빈 구간**과 "음…", "어…" 같은 **군말**을 잘라 템포를 빠르게 합니다(영상 편집 도우미의 "무음·군말 자동 컷"). 소리 분석은 모두 이 컴퓨터에서 하고 AI 서비스로는 아무것도 보내지 않습니다.

**어떻게 동작하나** (`cutPlan.ts`, `autoCut` 작업)
1. 서버가 영상의 소리를 한 번 분석합니다: 조용한 구간(ffmpeg `silencedetect`, 녹음 환경에 맞춘 기준 −42/−35/−28dB, 0.3초 이상 전부), 그리고 군말 찾기를 켰다면 음성 인식으로 **단어마다 시간**.
2. **무엇을 자를지는 화면에서 계산**합니다. 슬라이더("이 길이 이상 조용하면 자름" 0.3~2초, "자른 자리에 남길 숨" 0~0.6초)와 스위치를 바꿔도 서버를 다시 부르지 않고 바로 결과가 바뀝니다. 녹음 환경을 바꾸거나 군말 찾기를 새로 켰을 때만 다시 분석합니다(화면이 알려 줍니다).
3. 자를 곳 목록에서 **하나씩 체크를 끄고 켜고**, "▶ 앞뒤 3초 보기"로 그 자리를 들어 본 뒤 결정합니다. 원본 길이 → 결과 길이, 무음·군말 개수, 남는 조각 수가 실시간으로 보입니다.
4. "이 컷으로 영상 만들기"로 mp4를 만들거나, **컷 목록 EDL·텍스트**로 내보내 편집 프로그램에서 원본 해상도 그대로 쓸 수 있습니다.

**규칙**
- 무음은 기준 길이 이상일 때만 자르고, 숨을 남기려고 **앞뒤로 절반씩** 남깁니다(말이 서로 붙어 버리지 않게).
- 군말은 단어 하나의 시간 범위만 자릅니다. 기본으로 찾는 것은 "음·으음·어·에·엄·흠·으" 같은 **망설임 소리**입니다. "그·저·뭐·아·이제·막"은 진짜 단어이기도 해서 **옵션을 켰을 때, 0.5초 이상 길게 끌었을 때만** 군말로 봅니다. 그래도 평범한 단어를 잘못 고를 수 있어 목록을 확인하도록 되어 있습니다.
- 무음으로도 군말로도 잡힌 같은 자리는 **한 번만** 보여 줍니다(군말을 남기고 무음 줄을 뺌).
- 남는 조각이 0.3초보다 짧으면 버립니다(잠깐 번쩍이기만 하므로). 조각이 **400개를 넘으면** 영상 만들기는 막고(EDL·텍스트 내보내기는 가능) "이 길이 이상 조용하면 자름"을 늘리라고 안내합니다.
- 조각을 이을 때 **양 끝에 12ms 소리 페이드**를 넣어 이음매 잡음을 줄입니다(컷이 많은 편집에 효과가 큽니다).
- 결과 형식은 가로 1920×1080 또는 세로 쇼츠 1080×1920(3분 이하)이며, 원본이 가로면 가로가 기본입니다.

**한계**
- **군말 찾기는 실험 기능입니다.** 음성 인식(Whisper)은 군말을 일부러 빼고 적는 경향이 있어 **못 찾는 군말이 있을 수 있습니다**. 군말을 또렷이 발음한 합성 음성으로는 "음·어·으음"을 찾았지만, 사람이 웅얼거리듯 하는 실제 군말은 더 놓칠 수 있습니다. 앞 30분까지만 찾고, 처음 켤 때 모델 약 240MB를 내려받습니다.
- 무음 기준은 소리 크기만 보므로 배경음악이나 소음이 큰 영상은 잘 맞지 않습니다("주변 소음이 있음"을 고르거나 슬라이더를 조정).
- 영상으로 만들 때 화면은 위 두 형식으로 변환됩니다(원본 해상도·비율 그대로 컷만 하려면 EDL을 쓰세요).

## 자동 프레임 (가로 → 세로, 따라가며 자르기)

가로 영상을 세로(9:16) 쇼츠로 자를 때, 화면 전체를 흐린 배경 위에 얹는 대신 **사람(또는 동물·탈것)이 있는 쪽으로 꽉 차게 잘라** 움직이면 자르는 위치도 따라 움직입니다. 찾기는 모두 이 컴퓨터에서 하며 영상이나 화면은 어디로도 보내지 않습니다.

**쓰는 법**
- **영상 편집 도우미 → "자동 프레임"**: "찾기 시작" 후 아래를 눈으로 보며 조절하고, 구간을 정해 세로 쇼츠로 만듭니다. 모든 조절은 서버를 다시 부르지 않고 바로 반영됩니다.
  - **무엇을 따라갈까요**: 사람 / 동물 / 탈것(자동차·자전거·오토바이·버스·기차·배 등) / 모두.
  - **여럿이면 따라갈 것을 고르기**: 미리보기 사진 속 상자(#번호)를 누르거나 목록에서 체크합니다. 고르지 않으면 모두가 한 화면에 들어올 때는 가운데, 안 들어올 때는 가장 크게 보이는 것을 따라갑니다.
  - **확대**: 자동(대상이 작으면 키움, 최대 2배) / 안 함 / 1.5 / 2 / 3배. 확대하면 창이 작아져 **위아래로도 움직이며**(사람은 머리 위 여백을 두고 상체 중심), 원본에서 잘라 낸 작은 부분을 1080×1920으로 키우므로 **화면이 흐려집니다**(화면에 실제 잘리는 픽셀 크기를 보여 줍니다).
  - **카메라 움직임**(1 바짝 따라감 ~ 5 천천히)과 "가운데 고정".
- **"2-2. 세로 화면"에서 "따라가며 자르기"를 켜면** 쇼츠 뽑기·한 편 자동 편집·무음 컷의 세로 결과도 같은 방식으로 만들어집니다(대상 종류·확대·움직임 선택 가능, 만들기 전에 찾는 단계가 먼저 돕니다). 기본은 꺼져 있고, 특정 사람 지정은 "자동 프레임" 도구에서만 됩니다.

**어떻게 동작하나** (`subjectDetector.ts`, `subjectTrack.ts`, `reframe.ts`, `render.ts`)
1. 0.5초마다(긴 영상은 최대 600장으로 간격을 늘려) 작은 화면을 뽑아 **YOLOS-tiny**(Xenova/yolos-tiny, 약 9MB, COCO 80종 중 사람·동물·탈것만 사용, 처음 한 번 내려받음)로 찾습니다. 한 장에 약 0.35초(CPU). 실제로 쓸 구간(자른 조각들)만 봅니다.
2. 찾은 결과(상자와 종류)를 그대로 화면에 보내고, **번호 매기기**(앞 장면의 상자와 겹치거나 가까운 같은 종류면 같은 번호, 1.6초 넘게 안 보이면 새 번호)도 화면에서 합니다.
3. 대상이 여럿이면 **모두 한 창에 들어올 때는 그룹의 가운데**, 안 들어올 때는 가장 크게 보이는 것(직전 위치와 이어지게)을 고릅니다. 지정한 것만 따라갈 때 그것이 안 보이는 장면은 다른 사람으로 튀지 않고 카메라가 마지막 자리를 잠시 지킨 뒤 가운데로 천천히 돌아옵니다.
4. 카메라 경로를 만듭니다(좌우, 확대 시 위아래도): 못 찾은 구간은 마지막 위치를 유지하다 가운데로 돌아오고, 한 장짜리 오검출은 무시하며, 사소한 흔들림은 무시(데드존)하고, 속도에 상한을 둡니다. 영상 자체가 장면 전환으로 크게 건너뛴 곳에서는 카메라도 같이 건너뜁니다.
5. 렌더링에서 ffmpeg `crop`의 위치(x, y)를 **명령 파일(`sendcmd`)로 시간에 따라 바꿉니다.** 조각을 이어 붙이는 편집에서도 각 조각의 원본 시간에 맞춰 경로가 따라갑니다.

**한계**
- **실제 영상 검증은 아직 적습니다.** 사람 사진이 움직이는 합성 영상(1명 이동, 2명 중 한 명 지정, 2배 확대, 조각 이어 붙이기)과, 무료 라이선스 스톡 영상 3개(개와 주인이 걷는 공원, 뒷모습 남자가 길을 건너는 장면, 팟캐스트 스튜디오의 두 사람)로 확인했습니다. 스톡 영상에서는 개·뒷모습 사람이 잘 따라갔고, 두 사람이 화면 양 끝에 앉은 장면은 한 창에 못 담아 한 명만 따라가며 다른 사람은 직접 지정해야 했습니다. 직캠·무대·빠른 움직임·어두운 조명에서는 직접 결과를 확인해 주세요. 개 영상에서는 멀리 주차된 자동차(103건)가 "모두" 대상에서 카메라를 끌어서, 주 대상 면적의 10% 미만인 것은 배경으로 보고 제외하도록 고쳤습니다. 모델이 개를 곰·소·말로 잘못 부르는 장면도 있어 동물 종류는 구분하지 않고 한꺼번에 "동물"로 다룹니다.
- 모델은 **얼굴이 아니라 몸 전체 상자**를 찾습니다. 얼굴 크기·방향은 보지 않으므로 몸이 가려지면 놓치고, 찾은 비율이 40% 미만이면 결과에 경고를 띄웁니다.
- **말하는 사람을 구분하지는 않습니다.** 여럿이면 직접 지정하거나 가장 크게 보이는 것을 따릅니다. (소리와 입 모양으로 구분하는 오픈소스 모델이 있지만 무겁고 변환이 필요해 넣지 않았습니다.)
- 같은 사람인지는 **위치와 크기로만** 판단합니다(얼굴 식별은 하지 않음). 사라졌다가 8초 안에 거의 같은 자리·크기로 돌아오면 같은 번호로 잇지만, 다른 곳에서 나타나거나 오래 뒤에 돌아오면 번호가 달라질 수 있어 두 번호를 모두 체크해야 합니다. 목록에는 한 장에서만 보인 번호(대개 오검출)를 빼고 보여 줍니다.
- 확대는 크게 할수록 흐려지고, 확대 배율은 영상 전체에 하나로 적용됩니다(장면마다 바뀌지 않음).
- 원본이 이미 세로이거나 결과가 가로인 경우에는 적용되지 않습니다.

## 전환·효과음 자동 삽입

컷이 이어지는 자리에 화면 전환과 효과음을 자동으로 넣습니다(영상 편집 도우미의 "2-3. 전환·효과음"). 고른 설정은 그 페이지에서 만드는 모든 영상(쇼츠 뽑기, 한 편 자동 편집, 무음·군말 컷)에 적용되며, 기본은 모두 꺼져 있습니다.

- **화면 전환**: 하얀 번쩍임(밝기가 0.12초 올랐다 내려감) / 잠깐 어두워짐(0.1초 검게) / 살짝 확대(컷 직후 7% 확대가 0.3초에 걸쳐 풀림). 길이를 늘이거나 겹치는 전환(디졸브 등)이 아니라서 **영상 길이와 자막 타이밍이 바뀌지 않습니다.** 화면 필터는 글자보다 먼저 걸려 자막이 번쩍이거나 확대되지 않습니다.
- **컷 효과음**: 휙(whoosh, 컷에 맞춰 0.2초 전부터 커짐) / 톡(pop) / 딱(tick). 그 밖에 후크 글자가 나올 때 "톡", 엔딩 카드가 나올 때 "띵"을 켤 수 있고, 크기는 10~100%입니다.
- **어느 컷에 넣나** (`effects.ts`): 컷에서 **원본을 1초 이상 건너뛴 곳**(장면이 바뀌는 곳)만, 서로 **1.5초 이상** 떨어진 곳에, 시작·끝 0.3초 안은 빼고 **최대 40곳**. 짧은 무음을 잘라 낸 점프컷마다 넣으면 정신없어서 기본은 빼 두었고, "짧은 무음 컷에도 넣기"를 켜면 넣습니다. 넣을 곳이 없으면 결과에 그렇게 알려 줍니다.
- **효과음은 합성음입니다.** 소리 파일을 받거나 쓰지 않고 ffmpeg가 잡음·사인파로 직접 만들어 저작권 걱정이 없지만, 전문 효과음 라이브러리만큼 다양하거나 세련되지는 않습니다. 원래 소리가 없는 영상에도 효과음이 들어가면 소리 트랙이 생깁니다(조용한 곳은 무음).
- **한계**: 한 덩어리로 자르는 쇼츠(컷 없음)에는 후크·엔딩 소리만 들어갑니다. 효과음의 어울림은 귀로 확인해 주세요(자동 테스트는 소리가 들어갔는지, 어디에 있는지를 크기로만 확인합니다). 영상 편집 도우미 밖의 화면(채널 분석 쪽 쇼츠 만들기)에는 아직 선택 화면이 없습니다.

## 박자에 맞춰 효과 넣기

영상 속 음악의 박자를 찾아서 박자마다 번쩍임·확대·효과음을 넣습니다(영상 편집 도우미의 "박자에 맞춰 효과 넣기"). 영상과 소리는 내 컴퓨터에서만 처리되고 AI도 쓰지 않습니다(비용 0).

- **박자 찾기**: ffmpeg가 소리를 22.05kHz 숫자열로 뽑고, MIT 라이선스의 [music-tempo](https://github.com/killercrush/music-tempo) 패키지(Simon Dixon의 BeatRoot 알고리즘)가 템포와 박 위치를 찾습니다(`beatAnalysis.ts`). 한 번에 최대 10분을 듣고(그대로 만들 때 결과는 최대 3분), 이 패키지는 1분에 60~200박 사이만 찾습니다. 이 패키지는 44.1kHz 소리를 가정해서 샘플레이트에 맞는 창 크기와 시간 간격을 따로 넘겨 줍니다(처음엔 이를 빠뜨려 박자 시각이 절반으로 나왔고, 테스트로 잡아 고쳤습니다).
- **화면에서 맞추기**(`beats.ts`, 서버를 다시 부르지 않고 바로 반영): 템포 절반·두 배(박자 추적기는 한 옥타브 틀리게 잡는 일이 흔합니다), ±250ms 위치 조절, 모든 박·2박마다·4박마다(어느 박부터인지 선택), 시작과 끝을 박에 맞춰 자르기. 박이 얼마나 고른지(`regularity`)를 "박자가 고름 / 조금 불규칙 / 불규칙"으로 알려 주고, 불규칙하면 어긋날 수 있다고 경고합니다. 박 위치는 그림으로 보여 줍니다.
- **효과**: 기존 전환·효과음(번쩍임·어두워짐·확대, 휙·톡·딱)을 컷 대신 박 시각에 넣습니다(`effects.beatTimes`). 박에서는 효과가 컷보다 자주 생기므로 간격은 0.18초 이상, 개수는 최대 400개(번쩍임·어두워짐 150, 확대 100)입니다. 먼저 15초만 만들어 확인한 뒤 전체(최대 3분)를 만들 수 있습니다.
- **박에 맞춰 줄이기(몽타주)**: 최대 10분 구간에서 4박(한 마디) 또는 8박 조각을 고르게 뽑아 이어 붙여 약 15·30·45·60초로 줄입니다(`planBeatCuts`). 조각은 박에서 시작해 박에서 끝나고 첫 박에서 조각 길이의 배수 위치에서만 시작하므로 겹치지 않고 마디가 어긋나지 않아, 이어 붙여도 박자가 이어집니다. 효과는 이어 붙인 결과의 박에 넣습니다(`beatsInResult`). 뽑는 방식은 **구간 전체에서 고르게**(기본) 또는 **소리가 큰 곳 위주**(0.25초마다 소리 세기를 재서 가장 센 조각을 뽑아 원래 순서로 이음, 한곳에 몰릴 수 있음)입니다. **장면(화면)은 보지 않고 소리 크기가 좋은 장면을 뜻하지도 않으므로**(후렴이나 드롭이 크게 들린다는 가정입니다) 결과를 보고 판단해 주세요. 먼저 15초만 만들어 볼 수 있습니다.
- **확인한 것**: ffmpeg로 만든 킥드럼 소리(120·140 BPM)에서 템포가 ±2 BPM 안으로, 박이 킥 위치의 0.06초 안으로 잡히고, 구간 지정과 소리 없음·너무 짧음 처리, 박 위치에서만 번쩍이는지(실제 렌더)를 자동 테스트로 확인했습니다. 브라우저로 30초 합성 영상을 박자 분석 → 15초 만들기까지 돌려 보니 번쩍임이 0.5초 간격으로 킥에 맞춰 들어갔고, 90초 합성 영상을 몽타주로 줄인 결과(16초)를 다시 분석하니 120.2 BPM에 규칙성 1.0으로 박자가 이어졌습니다.
- **한계**: **실제 음악·사람 목소리가 섞인 영상으로는 시험하지 못했습니다.** 합성한 북소리는 가장 쉬운 경우라, 드럼이 약하거나 박자가 자유로운 곡, 말소리가 큰 영상에서는 박이 어긋나거나 템포를 두 배·절반으로 잡을 수 있습니다(위 조절로 고치는 방식이지만 얼마나 자주 필요한지는 모릅니다). 박은 소리의 세기 변화에서 찾으므로 곡의 "첫 박(마디 머리)"을 알아내지는 못해 "어느 박부터"는 눈과 귀로 골라야 합니다. 효과의 어울림은 귀로 확인해 주세요.

## 자막 스타일과 내보내기

**자막 스타일** (`captionStyle.ts`): 훅 자막과 구간 자막의 모양을 화면에서 고릅니다. 고른 스타일은 그 화면의 모든 영상 만들기에 적용됩니다.

| 항목 | 선택지 |
|---|---|
| 스타일 | 기본(검은 박스) · 굵은 외곽선 · 노란 강조 · 미니멀(작은 박스, 더 작은 글자) |
| 자막 위치 | 위 · 가운데 · 아래 (훅 자막은 항상 위쪽, 위 위치의 구간 자막은 훅 아래) |
| 글자 크기 | 작게(0.8배) · 보통 · 크게(1.25배) — 줄 길이도 크기에 맞춰 바뀜 |

- 선택지마다 **미리보기 그림**이 있고, 영상에 들어가는 것과 **같은 설정으로 같은 엔진이 그린 것**입니다(`/api/stylepreview`, 한 번 그린 그림은 재사용, 하루 지나면 정리).
- 기본값은 스타일 기능이 생기기 전의 출력과 **글자 하나까지 같습니다**(테스트로 고정). 모르는 값이 오면 오류 없이 기본값으로 처리합니다. 엔딩 카드는 스타일의 영향을 받지 않습니다.

**편집 프로그램으로 내보내기** (`exporters.ts`): 쇼츠 후보, 편집 계획, 지시서로 만든 쇼츠마다 버튼이 있습니다.

- **자막 SRT**: 편집된 영상의 시간 기준(UTF-8). CapCut·Premiere·DaVinci에서 자막으로 불러올 수 있습니다. 기본은 **대사 자막만** 넣고, 훅·엔딩 문구는 체크하면 함께 넣습니다(둘은 자막이라기보다 제목이라 편집기에서 겹쳐 보일 수 있음).
- **컷 목록 EDL**(CMX 3600, Non-drop): 남길 구간을 원본의 시간 코드로 적습니다. Premiere·DaVinci Resolve에서 컷 편집으로 불러옵니다. EDL은 시간을 프레임으로 적기 때문에 **원본 영상의 프레임 레이트(24·25·30·50·60)를 맞춰** 골라야 합니다(기본 30fps; 29.97처럼 정수가 아닌 값은 지원하지 않음).
- **컷 목록 텍스트**: 불러오기가 안 되는 편집기(CapCut 등)에서 보고 따라 할 "원본 몇 분 몇 초 → 결과 몇 분 몇 초" 목록.

## 자동 수집

새 영상 감지, 체크포인트 결과 기록, 알림은 `collectOnce`(`src/lib/channel/collector`) 하나로 처리되고, 세 가지 방법으로 실행됩니다.

| 방법 | 설명 |
|---|---|
| 내장 타이머 | `npm run dev`/`npm start`로 앱이 켜져 있으면 시작 1분 뒤와 이후 6시간마다 자동 실행. `AUTO_COLLECT=off`로 끄고, `COLLECT_INTERVAL_HOURS`, `COLLECT_FIRST_DELAY_SEC`로 조절 |
| 성과 추적 탭의 "지금 수집" | 수동 실행 |
| `npm run collect` | 웹 서버 없이 한 번 실행. 앱을 항상 켜 두지 않는다면 Windows 작업 스케줄러에 등록해서 쓰세요 |

작업 스케줄러 예시(직접 실행, 매일 오전 9시):

```bash
schtasks /create /tn "YT Growth Coach collect" /sc daily /st 09:00 /tr "cmd /c cd /d C:\Projects\yt-growth-coach && npm run collect"
```

- 첫 실행은 이미 있는 영상을 "본 영상"으로만 기록하고 알림을 만들지 않습니다.
- 감지된 새 영상은 "자동 감지"로 표시되며, 성과 추적 탭에서 시도한 요소를 체크해 주세요.
- 결과는 **처음 확정된 시점의 값으로 고정 저장**되어 기준선을 다시 계산해도 기록이 바뀌지 않습니다.
- Analytics가 날짜별 과거 데이터를 제공하므로 앱이 꺼져 있어도 데이터가 사라지지는 않습니다. 자동 수집은 새 영상 감지와 알림, 결과 고정을 담당합니다.

## 원클릭 준비와 주간 자동 실행

AI 추천 탭의 "원클릭 준비"는 `runPrepare`(`src/lib/channel/prepare`) 하나로 처리되고, 세 가지로 실행됩니다.

| 방법 | 설명 |
|---|---|
| 카드의 "지금 준비하기" | 수동 실행. 진행 단계가 표시되고 끝나면 아래 추천·패키지가 새로 불러와짐 |
| 주간 자동 실행 | 카드에서 요일·시간을 정해 켬. 앱이 켜져 있으면 30분마다 확인해 예약 시각이 지났고 아직 실행하지 않았다면 실행. 꺼져 있었다면 앱을 켠 뒤 이어서 **주 1회만** 실행. 켜는 순간 바로 실행하지 않고 다음 예약 시각을 기다림. `AUTO_WEEKLY=off`로 끔 |
| `npm run prep` | 웹 서버 없이 실행. `-- --if-due`를 붙이면 주간 예약이 도래했을 때만 실행(작업 스케줄러용) |

- **필수 단계**(실패하면 중단): 채널 데이터, AI 추천. **선택 단계**(실패해도 계속): 트렌드, 제작 패키지(아이디어별), 소재 후보.
- 주간 실행이 실패하면 **6시간 동안 다시 시도하지 않습니다**(실패한 호출이 반복되어 비용이 나가는 것을 막기 위함).
- 한 번에 하나만 실행됩니다. 목표는 지난번 추천에서 이어받습니다.
- 1회에 Anthropic API를 (패키지 수 + 2)번 호출하고, 소재 후보를 켜면 YouTube 할당량 약 600이 듭니다.

## AI 자동 편집

영상 제작 탭의 "C. AI 자동 편집"은 `analyzeVideo`(FFmpeg로 분석) → `planEdit`(Claude가 장면 이미지를 보고 계획) → `sanitizePlan`(계획 검증·정리) → 기존 렌더러(`segments` 옵션) 순서로 동작합니다.

- **AI가 보는 것**: 대표 장면 최대 16장(640px), 장면 전환 시각, 무음 구간, 초당 소리 크기, 그리고 음성 인식을 켰다면 대사 텍스트(시간 포함). 음성 인식을 켜지 않으면 **대사·가사는 듣지 못하므로** 자막이 보이는 장면과 분위기 기준입니다.
- **음성 인식**(체크박스): `@huggingface/transformers`로 Whisper small(양자화)을 **이 컴퓨터에서** 실행합니다. 처음 한 번만 모델(약 240MB)을 Hugging Face에서 내려받아 `.data/models/`에 저장하고, 이후에는 인터넷 없이 동작합니다. 기본 언어는 한국어이고, 영상 소리 자체는 밖으로 나가지 않습니다. 앞쪽 30분까지만 인식하며, 무음 위에 지어낸 문구·같은 줄 반복·"시청해 주셔서 감사합니다" 같은 상투 문구는 걸러 냅니다. 대사를 알면 컷이 문장 중간에 떨어지지 않도록 가까운 문장 경계(1.5초 이내)로 옮깁니다. 인식 결과는 틀릴 수 있으니 자막을 확인하세요. 속도는 CPU에서 영상 길이의 몇 분의 1~비슷한 정도입니다.
- **전송되는 데이터**: 장면 이미지 몇 장과 분석 숫자(음성 인식을 켰다면 인식된 대사 텍스트 포함)가 Anthropic API로 전송됩니다. 영상 파일과 소리는 이 컴퓨터를 떠나지 않습니다. 대사·영상 속 글자는 "내용"으로만 취급하도록 지시해 두었습니다.
- **정리 규칙**: 구간은 파일 안으로 자르고 겹침·0.8초 미만 구간 제거, 길이 제한(쇼츠 180초) 초과분은 뒤에서부터 제외, `[대괄호]` 문구 제거, 겹치는 자막 정리, 컷으로 사라진 구간의 자막 삭제. AI가 쓸 만한 구간을 주지 않으면 앞부분을 그대로 쓰고 경고를 표시합니다.
- **권리 확인**은 기존 편집 자동화와 같습니다. 직접 촬영했거나 사용 허락을 받은 영상만 분석·렌더링합니다. 방송 영상을 내려받거나 자동으로 모으는 기능은 없습니다.
- 계획 단계 AI 호출은 1회이고, 분석 시간은 영상 길이에 비례합니다(분석 임시 파일은 끝나면 삭제됩니다).

### 긴 영상에서 쇼츠 뽑기 (D)

`highlights.ts`가 같은 분석(`analyzeVideo`)과 음성 인식 결과를 받아 후보 구간을 고릅니다.

- 후보는 원본 시간 기준 8~90초 구간이며(쇼츠 한도 180초 이내), 파일 밖·너무 짧은 것·더 높은 점수 후보와 절반 넘게 겹치는 것은 제외하고 점수순으로 최대 6개만 남깁니다. 마땅한 구간이 적으면 후보도 적게 나옵니다(내용이 없는 영상에는 낮은 점수를 줍니다). 길이는 기본 15~60초를 권하지만 내 채널의 잘된 길이 범위가 있으면 그쪽을 우선합니다.
- 음성 인식을 켰다면 컷 지점이 문장 중간에 떨어지지 않게 조정하고, 그 구간의 **대사가 자막으로 자동 생성**됩니다(긴 문장은 짧게 나누고 시간은 글자 수에 비례해 배분, 1초 미만으로 깜빡이는 자막은 만들지 않음). 말이 없는 영상은 훅 자막만 붙습니다.
- 긴 영상은 대표 장면을 24장까지 AI에게 보여 줍니다. 분석 시간은 영상 길이에 비례하며, 1시간짜리 영상은 파일 경로로 넣는 것을 권합니다(업로드는 600MB까지, 후보마다 렌더링할 때 다시 올라감).
- **내 채널 성과 반영**: 후보를 고를 때 내 채널의 점수가 매겨진 쇼츠(7일 이상 지난 것)를 함께 참고합니다. 잘된 쇼츠 5개, 부진한 쇼츠 3개(제목·길이·점수·지속률·구독 전환)와 패턴을 AI에게 주고, 점수 상위 3분의 1 쇼츠의 길이 범위(25~75백분위)를 계산해 후보마다 "내 채널 잘된 길이 / 더 짧음 / 더 김" 표시를 붙입니다. 길이 범위는 점수가 있는 쇼츠가 **6개 이상**일 때만 만들고, 3개 미만이면 채널 자료 자체를 쓰지 않습니다. 로그인이 안 됐거나 불러오기에 실패하면 채널 자료 없이 그대로 진행합니다. 이 자료는 길이와 스타일의 참고일 뿐, 영상에 없는 내용을 만들어 내지 않도록 지시해 두었습니다.
- 점수는 AI의 판단일 뿐 조회수를 보장하지 않습니다. 후보는 직접 확인하고 훅 자막은 고쳐서 쓰세요.
- 권리 확인과 데이터 전송 범위는 위 AI 자동 편집과 같습니다. 방송·타사 영상을 내려받거나 자동으로 모으는 기능은 없습니다.

#### 영상 주소로 분석 (E)

`urlPlan.ts`가 YouTube의 **공개된 정보만** 읽어 분석합니다. **AI는 영상을 보거나 듣지 못합니다.** 근거는 다음 다섯 가지이고 결과 화면에 몇 개씩 썼는지 표시됩니다.

- 제목·설명·길이·조회수
- 업로더의 챕터(설명의 타임스탬프; 줄 맨 앞에 시간이 있을 때만 챕터로 인식)
- 시간을 짚은 댓글(예: "3:27 여기 최고"): 관련도 순 최대 300개 중 시간 표시가 있는 것
- 반응이 큰 댓글(좋아요 순 15개): 시청자가 무엇에 반응하는지
- YouTube가 임베드용으로 제공하는 미리보기 이미지 4장(대표 이미지 1장 + 영상 중간 장면 3장). 장면의 시간 정보는 없으므로 구간을 정하는 근거로는 쓰지 않고 내용 파악에만 씁니다.

자막(대본)은 읽지 않습니다. YouTube가 자막 주소를 막아 두어(빈 응답) 우회하는 방법은 불안정하고 약관상 문제가 있어 넣지 않았습니다.

- 시간이 가까운 댓글(12초 이내)을 한 "순간"으로 묶고, 가중치는 좋아요 수 + 댓글 1개당 1입니다. 여러 사람이 짚은 순간이 하나의 큰 댓글보다 높게 쳐집니다.
- 결과: **영상 요약**(무엇을 근거로 했는지 포함), **내 채널에서 쓸 주제**(각도와 근거), **제목 후보 5개**, **쇼츠 후보**(파일 분석 D와 같은 규칙으로 정리: 영상 안, 8~90초, 겹침 제거, 점수순, 내 채널의 잘된 길이 범위 표시), **롱폼 구성안**(3~8개 구간·챕터·제목·설명, 아래 롱폼 규칙과 같은 챕터 처리).
- **시간 단서(시간을 짚은 댓글이나 챕터 2개 이상)가 없으면** 요약·주제·제목만 만들고, 쇼츠 구간과 롱폼 구성안은 AI가 내더라도 버립니다(근거 없는 구간은 추측이므로). 댓글을 읽지 못한 경우(`YOUTUBE_API_KEY` 없음, 댓글 막힘)에도 안내합니다.
- 쇼츠 후보의 **편집 지시서**에는 원본·구간·시간 링크·이유·시청자 반응·훅·제목·설명에 넣을 출처 문구·편집 방법이 들어 있어 CapCut 같은 편집기에서 그대로 따라 할 수 있습니다.
- 내려받기·복사를 하지 않으므로 분석 자체에는 권리 확인 체크가 없지만, **원본을 쓸 권리는 직접 확인**해야 합니다. 영상 파일을 YouTube에서 받아 오는 기능은 넣지 않았습니다.
- 영상 파일을 이미 가지고 있다면 같은 화면의 "파일로 바로 만들기"에 넣어 지시서·롱폼 구성안을 바로 영상으로 만들 수 있습니다(아래).
- D(쇼츠 뽑기)의 "원본 영상 주소" 칸에 같은 주소를 넣으면 이 댓글 인기 구간을 후보 선정에 함께 반영합니다. 파일 길이가 주소의 영상 길이와 5% 넘게 다르면 다른 영상(편집본 등)으로 보고 반영하지 않습니다.
- **지시서로 쇼츠 만들기**: 그 영상의 파일을 이미 가지고 있다면(직접 구한 파일) 후보의 "이 지시서로 쇼츠 만들기"로 분석 없이 바로 그 구간을 만듭니다. 파일(업로드 또는 경로)과 **권리 확인**(필수)을 넣으면 ① 파일 길이를 원본 영상과 비교하고(5% 넘게 다르면 경고하고 "그래도 이 시간대로 만듭니다"에 체크해야 진행), ② 음성 인식을 켰다면 **그 구간의 대사만** 인식해 자막으로 채웁니다. 훅과 자막을 고친 뒤 만들면 1080×1920 쇼츠가 만들어지고, 그 후보는 AI 점수 검증용으로 기록됩니다. **롱폼 구성안**은 "파일 길이 확인"으로 같은 비교를 한 뒤(다르면 체크해야 진행) 1920×1080 롱폼으로 만듭니다.
- 텍스트(댓글·설명)를 AI로 보낼 때 이모지가 중간에서 잘려 생긴 깨진 글자가 있으면 API가 요청 전체를 거부하므로, 자를 때 이모지를 쪼개지 않고 보내기 직전에 한 번 더 정리합니다.
- D(쇼츠 뽑기)의 "원본 영상 주소" 칸에 같은 주소를 넣으면 이 댓글 인기 구간을 후보 선정에 함께 반영합니다. 파일 길이가 주소의 영상 길이와 5% 넘게 다르면 다른 영상(편집본 등)으로 보고 반영하지 않습니다.

#### 구간 미리 보기, 자막 편집

- **미리 보기**: 파일 경로로 넣은 영상은 서버가 그 구간만 360p로 빠르게 인코딩한 작은 복사본(`.data/previews/`, 하루 지나면 자동 삭제, 같은 구간은 다시 만들지 않음)을 보여 줍니다. 파일을 업로드한 경우에는 브라우저가 올린 파일을 직접 재생하며 구간 끝에서 멈춥니다(브라우저가 못 여는 형식은 파일 경로로 넣으면 됩니다). 원본 화면만 보여 주므로 훅·자막·세로 프레임은 만든 뒤 결과에서 확인하세요.
- **자막 편집**: 후보 카드에서 자막의 글자와 시작·끝 시간(이 쇼츠 시작을 0초로 한 초 단위)을 고치거나 줄을 추가·삭제하고 "처음 상태로"로 되돌릴 수 있습니다. 글자가 비었거나 시간이 맞지 않는 줄은 영상에 넣지 않고 빨간 칸으로 표시합니다. 수정한 내용 그대로 렌더링됩니다.

#### 롱폼 요약 구성

"롱폼 요약 구성도 만들기"를 켜면 같은 분석으로 가로 롱폼 한 편의 계획도 만듭니다(AI 호출 1회 추가, 원본의 절반 안팎·1~15분, 2분 미만 영상은 만들지 않음). 컷·자막·제목 3안·설명·해시태그에 더해 **챕터**를 제안하고, 다음 규칙으로 정리합니다.

- 챕터는 편집 후 영상의 시간으로 바꾸고, 잘려 나간 구간의 챕터는 다음 남은 구간의 시작으로 옮깁니다.
- YouTube가 설명의 시간표를 챕터로 인식하는 조건에 맞춥니다: 0:00부터 시작(처음 챕터가 10초 이상 뒤면 "오프닝"을 추가), 챕터 간격 10초 이상, **3개 미만이면 챕터를 넣지 않습니다**.
- 챕터 목록(`0:00 오프닝` 형식)은 설명 끝에 자동으로 붙고, 렌더링할 때 첫 챕터를 뺀 각 챕터에 4초짜리 제목 카드가 뜹니다(그 자리의 다른 자막은 카드에 자리를 내줍니다).
- AI 자동 편집(C)에서 롱폼 아이디어를 고른 경우에도 같은 챕터 처리가 적용됩니다.

#### AI 점수 검증

쇼츠를 만들면 그 후보의 AI 점수·이유·제목·구간이 `.data/clips.json`에 기록됩니다. 성과 추적 탭의 "AI 점수 검증"에서 올린 영상 목록(또는 주소 붙여넣기)으로 연결하면 비교합니다. 한 영상은 한 쇼츠에만 연결할 수 있습니다.

- 비교 대상은 영상의 **품질 점수**(내 쇼츠 안에서의 백분위, 업로드 7일 이후 매겨짐)입니다.
- 순위 상관이 0.5 이상이면 "맞는 편", 0.2~0.5 약하게 맞음, −0.2~0.2 관계 없음, −0.2 이하 반대로 맞음입니다. **점수가 매겨진 연결 영상이 5개 미만이면 판단하지 않습니다**(4개부터 AI 점수 상·하위 절반의 평균 실제 점수는 보여 줍니다). 표본이 적을 땐 우연히 좋게 나올 수 있습니다.
- 이 결과는 AI 점수를 믿어도 되는지 판단하는 근거일 뿐, 자동으로 점수 산정에 반영되지는 않습니다.

### 음성 인식의 처리 방식

Whisper는 무음 위에 없는 말을 지어내거나("MBC 뉴스 ○○○입니다" 같은 맺음말) 긴 침묵을 건너뛰면서 시간이 틀어지는 문제가 있어, **소리가 있는 구간만 잘라서 따로 인식**하고 결과를 원래 시간 위치에 되돌립니다. 지어낸 맺음말, 깨진 글자, 같은 줄 반복, 무음 위의 문장은 걸러 냅니다.

## AI·처리 원가 측정

가격을 정하려면 작업 한 건에 얼마가 드는지 알아야 해서, 작업별로 **AI 토큰과 단계별 시간을 실제로 재어** 성과 추적 탭의 "AI·처리 원가"에 보여 줍니다.

- **측정 방식**: AI 호출은 `trackedClient`(`usage.ts`)를 거치고, 작업 단위(`tracked`)와 단계(`timed`)는 호출 흐름(비동기 컨텍스트)에 따라 해당 작업의 기록에 붙습니다. 쇼츠 뽑기·AI 자동 편집·영상 주소 분석·구간 자막·렌더링·AI 추천·제작 패키지·소재 후보 찾기·채널 파악이 대상이고, 기록은 `.data/usage.json`(최근 500건)에 저장됩니다. 측정이 실패해도 작업은 영향을 받지 않습니다. 생각(thinking) 토큰은 출력 토큰에 포함됩니다.
- **금액은 가정하지 않습니다.** 모델 단가(입력·출력, USD/100만 토큰)와 환율은 화면에서 **직접 입력**한 값으로만 계산하며, 입력 전에는 토큰과 시간만 보입니다.
- **표의 내용**: 작업별 횟수(실패 별도), 평균 토큰, 평균 AI 비용, 평균 시간, 단계별 평균 시간, 평균 원본 길이, 그리고 "작업 1건 가격 가정"을 넣으면 AI 비용을 뺀 마진(원, %). 실패한 작업은 평균에서 빼고 횟수에만 표시합니다.
- **포함되지 않는 것**: 서버 처리 비용(영상 처리는 지금 이 컴퓨터에서 하므로 0이지만 서버로 옮기면 처리 시간만큼 듭니다), 저장·전송비, 결제 수수료, 세금.

처음 측정 값(합성 영상·공개 영상 하나씩, 참고용): 영상 주소 분석 입력 8.4천/출력 3.8천 토큰·약 43초, 6.7분짜리 파일의 쇼츠 뽑기(음성 인식·롱폼 구성 포함) 입력 2.2만/출력 2.4천 토큰·약 58초(그중 음성 인식 25초), 렌더링은 AI 호출 없이 약 5초.

## 지표 정의

- **쇼츠**: 길이 3분 이하이면서 YouTube가 쇼츠로 취급하는 영상(아래 참고). 쇼츠 지속률이 100%를 넘는 것은 반복 재생이 포함되기 때문입니다.
- **품질 점수**: 같은 포맷 안의 백분위 가중 평균 — 조회 속도 20 · 지속률 30 · CTR 15 · 참여 15 · 구독 전환 20. 없는 지표는 제외하고 재정규화. 업로드 7일 미만은 미평가.
- **CVR**: 1천 조회당 신규 구독자. **CTA 반응**: `(댓글 + 공유) / 조회수`.
- **CTR**: YouTube Analytics API가 영상별 조회를 지원하지 않아 제외됩니다(Studio에서 확인).
- **성과 추적 기준선**: 내 기존 영상의 첫 N일(1·3·7·28) 누적 성적 분포. 새 영상과 같은 조건으로 비교합니다. **쇼츠와 롱폼은 따로** 계산하며, 한 형식의 기록이 5개 미만이면 그 기준선은 만들지 않고 해당 영상은 비교 없이 숫자만 표시합니다. 28일차는 천천히 쌓이는 롱폼을 위한 체크포인트입니다.
- **쇼츠/롱폼 구분**: 3분을 넘는 영상은 항상 롱폼입니다. 3분 이하 영상은 `youtube.com/shorts/<영상ID>`가 그대로 열리면 쇼츠, 일반 재생 페이지로 이동하면 쇼츠가 아닌 것으로 보고 롱폼으로 분류합니다(예: 3분 이하의 가로 영상). 공식 API가 아니라 **비공식 방법**이어서, 응답이 애매하거나 실패하면 판별하지 않고 길이 기준을 그대로 씁니다. 답은 영상별로 `.data/shorts.json`에 저장되며, 속도 제한을 피하려고 한 번에 최대 60개씩 하나씩 천천히 확인하므로 영상이 많은 채널은 데이터 새로고침을 몇 번 하면 모두 채워집니다. 내 채널과 연결한 영상에만 적용되고, 경쟁 채널·트렌드 영상은 길이 기준입니다.

## 시청 지속 분석

YouTube Studio에서 내려받은 **시청 지속률 데이터**(영상 하나, 위치와 지속률 두 열)를 붙여 넣으면 시청자가 어디서 떠나는지 찾아 줍니다(영상 편집 도우미의 "시청 지속 분석"). 영상 파일도 AI도 필요 없고, 계산은 모두 화면 안에서 하며 데이터는 어디로도 전송되지 않습니다(`retention.ts`, 비용 0).

세 가지를 따로 봅니다. 문제가 다르면 고치는 곳도 다르기 때문입니다(이 나눔은 MIT 라이선스의 [youtube-agent-skill](https://github.com/Jakeschincariol/youtube-agent-skill)의 시청 지속 해석에서 아이디어를 얻었고, 코드와 기준은 새로 작성했습니다).
- **도입 이탈**: 처음 30초(짧은 영상은 길이의 20%까지, 길이를 모르면 10%)에서 잃은 퍼센트포인트. 25%p 미만 무난, 40%p 이상 심각. **이 기준은 경험칙일 뿐 벤치마크가 아닙니다.** 같은 채널의 다른 영상과 비교해서 보세요.
- **급락**: 도입 이후, 한 걸음(곡선을 고르게 다시 잡은 간격)에서 잃은 양이 중간 값보다 크게 튀는 연속 구간(중간 값 + 3×중앙값 절대편차, 최소 0.7%p, 합계 1.5%p 이상), 큰 것 5곳까지.
- **완만한 하락**: 중간 구간에서 한 걸음당 잃는 중앙값. "10%마다 N%p", 길이를 알면 "1분에 N%p".
- 덤으로 **다시 돌려 본 곳**(지속률이 오른 구간, 3곳까지)을 보여 줍니다. 쇼츠 후보로 좋습니다.
- **가장 먼저 볼 것 하나**: 도입이 새면 도입, 아니면 5%p 이상 급락, 아니면 10%당 6%p 이상의 꾸준한 하락, 모두 아니면 "곡선은 괜찮으니 제목·썸네일을 보세요".
- 영상 길이(초 또는 분:초)를 넣으면 시각으로 말하고, **SRT 자막을 넣으면 급락한 순간에 무슨 말을 했는지** 함께 보여 줍니다. 곡선만 보므로 **"왜" 떠났는지는 알려 주지 못합니다.**
- **편집으로 바로 이어집니다(영상 파일을 올렸을 때).** 작업 고르기 다음의 "영상 올리기"는 이 도구에서는 건너뛰어도 되고, 올리면 (1) 급락한 곳 앞뒤 3초를 바로 재생해 볼 수 있고, (2) **다시 돌려 본 곳으로 쇼츠를 만들 수 있으며**(시청자가 되돌려 본 지점의 2초 전부터 15/30/45/60초, 영상 끝 근처면 길이를 유지하도록 앞으로 당김), (3) **급락한 곳을 빼고 다시 만든 시험용 편집본**(체크한 곳만 잘라 가로 또는 세로로 렌더링)을 만들 수 있습니다. 앞 단계의 꾸미기(자막 스타일, 따라가며 자르기, 전환·효과음) 선택이 그대로 쓰입니다. 구간을 초로 바꾸려면 영상 길이가 필요해서, 파일을 직접 올리면 길이가 자동으로 들어가고 경로로 지정했다면 직접 적어야 합니다. 급락의 원인이 그 장면이 아닐 수도 있어서 "빼기"는 재생해 본 뒤 고르라고 안내합니다. 2분짜리 테스트 영상으로 쇼츠(1:24 시작, 30초)와 편집본(117.6초, 2.4초 제거)이 의도한 구간으로 만들어지는 것을 확인했습니다.
- 입력은 쉼표·탭·세미콜론 구분, 머리글 있음/없음, `%`·`1:05` 형식, 0~1 비율을 알아서 읽고(처음 두 숫자만 사용), 짧은 영상을 초 단위로 내려받았을 때는 "첫 열의 단위"를 직접 고릅니다. **실제 Studio 내보내기 파일로는 아직 시험해 보지 못했습니다**(열 구성이 다를 수 있어 읽지 못하면 이유를 알려 줍니다).

## 코드 구조

한 저장소 안에서 세 덩어리로 나눴고, 서로 어디까지 닿을 수 있는지를 ESLint 규칙(`eslint.config.mjs`)이 막아 줍니다. 규칙을 어기면 `npm run lint`(CI 포함)가 실패합니다.

| 덩어리 | 위치 | 무엇 | 의존해도 되는 곳 |
|---|---|---|---|
| **editor** | `src/lib/editor`, `src/components/editor` | 영상 편집: 렌더링, 소리·장면 분석, 음성 인식, 자동 프레임, 전환·효과음, 박자 효과, 시청 지속 분석, 쇼츠 뽑기, 자동 편집 | shared, site |
| **channel** | `src/lib/channel`, `src/components/channel` | 채널 분석·추천·제작 패키지·성과 추적(Google 로그인 필요) | editor, shared, site |
| **shared** | `src/lib/shared` | 저장소(`.data`), 사용량·원가 측정, Google·YouTube 클라이언트, 공통 도구 | shared만 |
| **site** | `src/components/site` | 로고, 상단 메뉴, 아이콘, 소개 페이지 | site만 |

- `src/lib`은 컴포넌트를 불러오지 않습니다. 페이지·API 경로(`src/app`)는 어느 덩어리든 쓸 수 있는 조립 층입니다.
- **편집기는 채널 분석을 모릅니다.** "내 채널에서 잘된 쇼츠 길이 반영"처럼 채널 정보가 필요한 곳은 편집기가 받을 모양(`editor/clipProfile.ts`의 `ClipProfile`)만 정해 두고, 값은 `src/app/api/*`가 채널 쪽(`channel/channelProfile.ts`)에서 만들어 넘겨 줍니다. 채널 기능이 없어도(로그인 안 함, 공개 데모) 편집기는 그대로 돕니다.
- 이렇게 나눠 두었기 때문에, 편집 엔진(렌더링·분석·자동 프레임 등)만 따로 떼어 라이브러리나 CLI로 만들거나, 채널 분석을 별도 서비스로 키우고 싶을 때 잘라 내기 쉽습니다. 아직 그럴 이유가 없어 저장소는 하나로 둡니다.
- 린트가 이 구조를 어기는 임포트를 잡아낸 적이 한 번 있습니다(편집기의 주소 분석이 채널 폴더의 "브리프 → 영상" 패널을 쓰고 있어, 그 패널이 편집기 것이라고 보고 옮겼습니다).

## 실행·배포 (Docker, 공개 데모, CI)

- **내 컴퓨터에서 전체 기능**: `docker build -t cliplab .` 후 `docker run --rm -p 3000:3000 -v cliplab-data:/app/.data cliplab`(AI 기능은 `-e ANTHROPIC_API_KEY=…` 추가). 이미지에는 영상 처리 도구(ffmpeg)와 한글 글꼴(나눔)이 들어 있고, 음성 인식·사람 찾기 모델은 처음 쓸 때 `/app/.data`(볼륨)에 내려받습니다. 개발 의존성도 남겨 두어 이미지는 큽니다(약 3GB, TypeScript 설정 파일을 서버가 읽기 때문). **Windows의 Docker Desktop(엔진 29.7)에서 이미지를 빌드하고 컨테이너를 실행해 확인했습니다**: 첫 화면과 편집기가 열리고, 준비 상태에서 ffmpeg(글자 그리기 기능 포함)와 한글 글꼴이 정상으로 나오며, 컨테이너 안에서 한글 훅과 자막이 그려진 영상이 만들어지고, `--build-arg NEXT_PUBLIC_DEMO=1` 이미지에서는 API가 403, 채널 페이지가 첫 페이지로 넘어갑니다. 음성 인식·사람 찾기 모델 내려받기와 AI 호출은 컨테이너에서 시험하지 않았습니다.
- **공개 데모**: 같은 코드를 `NEXT_PUBLIC_DEMO=1`로 빌드하면(Docker는 `--build-arg NEXT_PUBLIC_DEMO=1`) 서버가 일해 주어야 하는 것은 모두 막습니다. `src/proxy.ts`가 모든 `/api/*`에 403과 이유를 돌려주고 `/channel`은 첫 페이지로 보내며, 편집기는 브라우저 안에서만 계산하는 **시청 지속 분석**만 열고 나머지 작업은 "내 컴퓨터에서 실행하면 사용"으로 잠급니다. 소개 페이지에는 직접 실행 방법이 나옵니다. 영상 업로드를 받지 않으므로 저작권 문제가 없고 AI 비용도 들지 않습니다. 운영 빌드를 직접 실행해 API 403, 채널 페이지 이동, 편집기 화면을 확인했고 **실제 호스팅(Vercel 등)에는 아직 올리지 않았습니다**(Vercel은 프로젝트를 가져오고 환경변수 `NEXT_PUBLIC_DEMO=1`만 넣으면 됩니다).
- **CI**: `.github/workflows/ci.yml`이 푸시마다 타입 검사, 린트, 테스트, 일반 빌드, 데모 빌드를 돌립니다(아직 GitHub에서 한 번도 돌려 보지 못했습니다).
- 참고: 이 과정에서 `package.json`의 `prepare` 스크립트(원클릭 준비)가 npm의 설치 훅 이름과 겹쳐 `npm install`/`npm ci`마다 저절로 실행될 수 있다는 것을 발견해 **`npm run prep`으로 이름을 바꿨습니다**(기존에 `npm run prepare`로 작업 스케줄러를 걸어 두었다면 명령을 바꿔야 합니다).

## 화면 스크린샷과 접근성

- 소개 페이지(`/`)의 화면 그림은 실제 앱을 찍은 것입니다(`public/shots/*.webp`, 테스트용 합성 영상 기준). 화면이 바뀌면 개발 서버를 켠 채로 `node scripts/capture-shots.mjs <소리에 쉼이 있는 영상>`을 실행해 다시 찍습니다(로컬 Chrome을 DevTools 프로토콜로 조종하며 추가 패키지는 필요 없습니다).
- 접근성: **axe-core 4.14.0**(MPL-2.0, 프로젝트 밖 임시 폴더에 설치해 실행; 이 저장소의 의존성이 아님)을 소개 페이지, 편집기 4단계(무음 컷 결과 화면 포함), 채널 분석 화면에 데스크톱(밝음·어두움)과 좁은 화면(375px, 320px)에서 돌려 위반 0건을 확인했습니다. 좁은 화면에서는 가로 넘침도 없습니다. 이 과정에서 고친 것: 제목 순서, 이름 없는 단계 버튼·선택창, 칩 위 보조 글자 명암비(4.05→4.58:1), 24px보다 작은 누르는 곳(라벨·요약·슬라이더·바닥글 링크).
- 키보드: 실제 키 입력(Tab, Enter, Space)으로 "작업 고르기 → 다음 → 영상 올리기" 흐름을 지나며 고친 것: 단계가 바뀔 때 포커스가 사라지던 것(이제 새 단계 제목으로 이동), 권리 확인 체크 직후 영상 칸이 접히며 포커스를 잃던 것(이제 접히지 않음), 끌어다 놓는 칸에 포커스 표시가 없던 것, 본문 건너뛰기 링크가 본문으로 가지 않던 것. 스크린 리더로 읽을 때의 느낌은 직접 확인하지 못했고, AI 결과 화면(후보·계획 패널)은 비용 때문에 점검에서 빠졌습니다. 글자색 명암비는 밝은 화면 기준 보조 글자 5.9:1입니다.

## 한계와 주의

- **방송·타사 영상을 내려받거나 자동으로 자르는 기능은 없습니다.** 소재 후보 찾기는 링크만 보여주며, 편집 자동화는 권리 확인에 체크한 영상에만 렌더링합니다. 권리 관계는 사용자 책임이며 권리자 정책을 직접 확인해야 합니다.
- 소재 후보의 "공식/팬 편집본" 표시는 제목·채널명으로 한 추정입니다.
- 인스타 릴스 성과 데이터는 수집하지 않습니다. 릴스는 성과 좋은 쇼츠의 재활용 아이디어로만 제안합니다.
- 패턴 인사이트는 상관관계이며 표본이 작으면 신뢰도가 낮습니다. 성과 추적은 영상 3개 미만이면 참고만 하세요.
- 토큰, 설정, 렌더 결과는 로컬 `.data/`에 저장됩니다(gitignore). 단일 사용자 로컬 실행용이며, 여러 사용자에게 서비스하려면 DB와 사용자별 세션이 필요합니다.
- 영상 편집에는 `ffmpeg-static`(프로젝트 내 설치)과 시스템 한글 폰트(맑은 고딕/나눔고딕)를 사용합니다. **Linux용 ffmpeg-static에는 글자 그리기(drawtext)가 없어** Linux에서는 시스템 ffmpeg를 설치하고 `FFMPEG_PATH`로 지정해야 하며(Docker 이미지는 이미 그렇게 되어 있음), 준비 상태가 이를 알려 줍니다.
- 이 도구는 자동 점검이 못 보는 것(실제 사람 목소리 영상에서의 군말 찾기, 직캠·무대 영상에서의 자동 프레임, 효과음의 어울림, 스크린 리더로 읽는 느낌, 실제 Studio 내보내기 파일의 시청 지속 분석)을 아직 충분히 시험하지 못했습니다. 각 기능 절의 한계를 함께 읽어 주세요.
