# YT Growth Coach

내 유튜브 채널 지표와 시장 트렌드를 바탕으로 **다음에 어떤 롱폼·쇼츠·릴스를 만들지** 추천하고, 제작 준비와 성과 검증까지 돕는 로컬 대시보드.

## 기능

| 탭 | 내용 |
|---|---|
| 내 채널 진단 | 영상별 품질 점수(조회 속도·시청 지속률·참여·구독 전환 CVR), CTA 반응률, 자동 회고, 제목·길이·요일 패턴. 점수·총 조회수·구독 전환순 정렬 |
| 트렌드 | 국가/카테고리별 인기 급상승, 경쟁 채널의 "평소 대비 터진 영상", 키워드별 상위 영상. **비슷한 채널 찾기**: 내 영상의 제목·해시태그로 채널을 파악하고, 후보 채널의 최근 영상 30개를 직접 확인해 같은 소재를 꾸준히 다루는 채널만 남김(해시태그만 끼운 채널은 제외하고 이유 표시) |
| AI 추천 | **원클릭 준비**: 버튼 하나로 채널 데이터·트렌드 갱신 → AI 추천 → 상위 1~3개 아이디어의 제작 패키지 → 1순위 아이디어의 소재 후보까지 이어서 실행(진행 단계 표시, 끝나면 알림). **주간 자동 실행**도 같은 카드에서 요일·시간을 정해 켤 수 있음. 한 줄 결론, 핵심 지표, 우선순위별 할 일, 영상 아이디어 6~8개. 결과는 저장됨. 아이디어마다 **제작 패키지** 생성. 쇼츠·릴스는 제목 3안, 훅 자막, 컷 구성, 엔딩 CTA, 고정 댓글, 설명, 해시태그, 업로드 시간, 확인할 빈칸. **롱폼**은 여기에 썸네일 문구 안, 오프닝 대본, 챕터(시간 포함), 이탈 방지 장치, 중간·엔딩 CTA가 붙고 설명에 챕터 목록이 자동으로 들어감 |
| 영상 제작 | **A. 소재 후보 찾기**: 아이디어에 맞는 원본 영상을 링크·타임스탬프·시청자 댓글 시간대로 안내(내려받지 않음, 공식/팬 편집본 추정 표시). **B. 편집 자동화**: 내가 권리를 가진 영상 파일에 훅 자막, 구간 자막(롱폼은 챕터 제목 카드), 엔딩 카드를 입혀 mp4 생성. 쇼츠·릴스는 1080×1920 세로(3분 이하), **롱폼은 1920×1080 가로**(최대 4시간). 렌더링은 백그라운드로 진행되며 진행률이 표시되고, 큰 파일은 업로드 대신 **이 컴퓨터의 파일 경로**를 입력할 수 있음 |
| 영상 제작 · C | **C. AI 자동 편집**: 영상 파일을 AI가 훑어보고(대표 장면 이미지, 장면 전환, 무음 구간, 초당 소리 크기) **버릴 부분을 컷하고, 훅·구간 자막과 제목 후보 3개·설명·해시태그를 제안**. 먼저 계획을 보여 주고 확인한 뒤 "이 계획으로 영상 만들기"로 렌더링(컷한 구간을 이어 붙이고 자막 시간도 편집 후 기준으로 자동 변환). **음성 인식**을 켜면 이 컴퓨터에서 대사를 글자로 바꿔(Whisper) 대사 자막과 문장 단위 컷에 반영 |
| 영상 제작 · D | **D. 긴 영상에서 쇼츠 뽑기**: 긴 영상 하나를 넣으면 AI가 쇼츠로 올리기 좋은 구간을 **점수·이유·훅·제목과 함께 최대 6개 후보**로 제안. 후보별로 **구간 미리 보기**(낮은 화질 복사본)와 **자막 편집**(음성 인식 오타 수정·추가·삭제)을 한 뒤 "쇼츠 만들기"(또는 모두 만들기)를 누르면 훅 자막과 대사 자막이 붙은 1080×1920 쇼츠가 렌더링됨. 옵션으로 같은 영상의 **롱폼 요약 구성**(컷·챕터·제목·설명, 1920×1080)도 함께 제안 |
| 성과 추적 · AI 점수 검증 | 쇼츠 뽑기로 만든 쇼츠를 실제로 올린 영상에 연결하면, AI가 준 점수가 실제 성과(업로드 7일 후 품질 점수)와 맞았는지 **순위 상관(Spearman)**으로 보여 줌 |
| 성과 추적 | 기존 영상의 첫 1·3·7·28일 성적으로 **쇼츠와 롱폼을 따로** 기준선을 만들고, 새로 올린 영상을 "상위 몇 %"로 비교. 시도한 요소(시리즈 태그, 엔딩 CTA 등)별 효과를 모아 다음 AI 추천에 반영. **자동 수집**: 새 영상을 감지해 추적을 시작하고, 1·3·7·28일차 결과가 확정되면 그 값을 기록하며 알림을 남김 |

## 실행

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run dev                  # http://localhost:3000
```

> OAuth 로그인은 앱 내장 브라우저에서 막히는 경우가 있어 **Chrome/Edge에서 `localhost:3000`** 으로 진행하세요.

### Google Cloud 설정 (최초 1회)

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트 생성(또는 기존 프로젝트 사용)
2. **API 및 서비스 → 라이브러리**에서 `YouTube Data API v3`, `YouTube Analytics API` 사용 설정
3. **Google 인증 플랫폼**: 사용자 유형 외부(테스트 중), **테스트 사용자에 내 구글 계정 추가**
4. **클라이언트 → OAuth 클라이언트 ID(웹 애플리케이션)**, 승인된 리디렉션 URI: `http://localhost:3000/api/auth/callback`
5. 클라이언트 ID/보안 비밀번호 → `.env.local`의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` (보안 비밀번호는 생성 직후에만 볼 수 있음)
6. **API 키**(영상 제작 탭의 댓글 기반 장면 힌트에 필요): 사용자 인증 정보 → API 키 만들기, **YouTube Data API v3로 제한** → `YOUTUBE_API_KEY`
7. `ANTHROPIC_API_KEY` 입력 (AI 기능용)

테스트 모드에서는 refresh token이 7일 뒤 만료되므로 그때마다 다시 연결해야 합니다.

## 자동 수집

새 영상 감지, 체크포인트 결과 기록, 알림은 `collectOnce`(`src/lib/collector.ts`) 하나로 처리되고, 세 가지 방법으로 실행됩니다.

| 방법 | 설명 |
|---|---|
| 내장 타이머 | `npm run dev`/`npm start`로 앱이 켜져 있으면 시작 1분 뒤와 이후 6시간마다 자동 실행. `AUTO_COLLECT=off`로 끄고, `COLLECT_INTERVAL_HOURS`, `COLLECT_FIRST_DELAY_SEC`로 조절 |
| 성과 추적 탭의 "지금 수집" | 수동 실행 |
| `npm run collect` | 웹 서버 없이 한 번 실행. 앱을 항상 켜 두지 않는다면 Windows 작업 스케줄러에 등록해서 쓰세요 |

작업 스케줄러 예시(직접 실행, 매일 오전 9시):

```bash
schtasks /create /tn "YT Growth Coach collect" /sc daily /st 09:00 /tr "cmd /c cd /d C:\Projects\yt-growth-coach && npm run collect"
```

- 첫 실행은 이미 있는 영상을 "본 영상"으로만 기록하고 알림을 만들지 않습니다.
- 감지된 새 영상은 "자동 감지"로 표시되며, 성과 추적 탭에서 시도한 요소를 체크해 주세요.
- 결과는 **처음 확정된 시점의 값으로 고정 저장**되어 기준선을 다시 계산해도 기록이 바뀌지 않습니다.
- Analytics가 날짜별 과거 데이터를 제공하므로 앱이 꺼져 있어도 데이터가 사라지지는 않습니다. 자동 수집은 새 영상 감지와 알림, 결과 고정을 담당합니다.

## 원클릭 준비와 주간 자동 실행

AI 추천 탭의 "원클릭 준비"는 `runPrepare`(`src/lib/prepare.ts`) 하나로 처리되고, 세 가지로 실행됩니다.

| 방법 | 설명 |
|---|---|
| 카드의 "지금 준비하기" | 수동 실행. 진행 단계가 표시되고 끝나면 아래 추천·패키지가 새로 불러와짐 |
| 주간 자동 실행 | 카드에서 요일·시간을 정해 켬. 앱이 켜져 있으면 30분마다 확인해 예약 시각이 지났고 아직 실행하지 않았다면 실행. 꺼져 있었다면 앱을 켠 뒤 이어서 **주 1회만** 실행. 켜는 순간 바로 실행하지 않고 다음 예약 시각을 기다림. `AUTO_WEEKLY=off`로 끔 |
| `npm run prepare` | 웹 서버 없이 실행. `-- --if-due`를 붙이면 주간 예약이 도래했을 때만 실행(작업 스케줄러용) |

- **필수 단계**(실패하면 중단): 채널 데이터, AI 추천. **선택 단계**(실패해도 계속): 트렌드, 제작 패키지(아이디어별), 소재 후보.
- 주간 실행이 실패하면 **6시간 동안 다시 시도하지 않습니다**(실패한 호출이 반복되어 비용이 나가는 것을 막기 위함).
- 한 번에 하나만 실행됩니다. 목표는 지난번 추천에서 이어받습니다.
- 1회에 Anthropic API를 (패키지 수 + 2)번 호출하고, 소재 후보를 켜면 YouTube 할당량 약 600이 듭니다.

## AI 자동 편집

영상 제작 탭의 "C. AI 자동 편집"은 `analyzeVideo`(FFmpeg로 분석) → `planEdit`(Claude가 장면 이미지를 보고 계획) → `sanitizePlan`(계획 검증·정리) → 기존 렌더러(`segments` 옵션) 순서로 동작합니다.

- **AI가 보는 것**: 대표 장면 최대 16장(640px), 장면 전환 시각, 무음 구간, 초당 소리 크기, 그리고 음성 인식을 켰다면 대사 텍스트(시간 포함). 음성 인식을 켜지 않으면 **대사·가사는 듣지 못하므로** 자막이 보이는 장면과 분위기 기준입니다.
- **음성 인식**(체크박스): `@huggingface/transformers`로 Whisper small(양자화)을 **이 컴퓨터에서** 실행합니다. 처음 한 번만 모델(약 240MB)을 Hugging Face에서 내려받아 `.data/models/`에 저장하고, 이후에는 인터넷 없이 동작합니다. 기본 언어는 한국어이고, 영상 소리 자체는 밖으로 나가지 않습니다. 앞쪽 30분까지만 인식하며, 무음 위에 지어낸 문구·같은 줄 반복·"시청해 주셔서 감사합니다" 같은 상투 문구는 걸러 냅니다. 대사를 알면 컷이 문장 중간에 떨어지지 않도록 가까운 문장 경계(1.5초 이내)로 옮깁니다. 인식 결과는 틀릴 수 있으니 자막을 확인하세요. 속도는 CPU에서 영상 길이의 몇 분의 1~비슷한 정도입니다.
- **전송되는 데이터**: 장면 이미지 몇 장과 분석 숫자(음성 인식을 켰다면 인식된 대사 텍스트 포함)가 Anthropic API로 전송됩니다. 영상 파일과 소리는 이 컴퓨터를 떠나지 않습니다. 대사·영상 속 글자는 "내용"으로만 취급하도록 지시해 두었습니다.
- **정리 규칙**: 구간은 파일 안으로 자르고 겹침·0.8초 미만 구간 제거, 길이 제한(쇼츠 180초) 초과분은 뒤에서부터 제외, `[대괄호]` 문구 제거, 겹치는 자막 정리, 컷으로 사라진 구간의 자막 삭제. AI가 쓸 만한 구간을 주지 않으면 앞부분을 그대로 쓰고 경고를 표시합니다.
- **권리 확인**은 기존 편집 자동화와 같습니다. 직접 촬영했거나 사용 허락을 받은 영상만 분석·렌더링합니다. 방송 영상을 내려받거나 자동으로 모으는 기능은 없습니다.
- 계획 단계 AI 호출은 1회이고, 분석 시간은 영상 길이에 비례합니다(분석 임시 파일은 끝나면 삭제됩니다).

### 긴 영상에서 쇼츠 뽑기 (D)

`highlights.ts`가 같은 분석(`analyzeVideo`)과 음성 인식 결과를 받아 후보 구간을 고릅니다.

- 후보는 원본 시간 기준 8~90초 구간이며(쇼츠 한도 180초 이내), 파일 밖·너무 짧은 것·더 높은 점수 후보와 절반 넘게 겹치는 것은 제외하고 점수순으로 최대 6개만 남깁니다. 마땅한 구간이 적으면 후보도 적게 나옵니다(내용이 없는 영상에는 낮은 점수를 줍니다). 길이는 기본 15~60초를 권하지만 내 채널의 잘된 길이 범위가 있으면 그쪽을 우선합니다.
- 음성 인식을 켰다면 컷 지점이 문장 중간에 떨어지지 않게 조정하고, 그 구간의 **대사가 자막으로 자동 생성**됩니다(긴 문장은 짧게 나누고 시간은 글자 수에 비례해 배분, 1초 미만으로 깜빡이는 자막은 만들지 않음). 말이 없는 영상은 훅 자막만 붙습니다.
- 긴 영상은 대표 장면을 24장까지 AI에게 보여 줍니다. 분석 시간은 영상 길이에 비례하며, 1시간짜리 영상은 파일 경로로 넣는 것을 권합니다(업로드는 600MB까지, 후보마다 렌더링할 때 다시 올라감).
- **내 채널 성과 반영**: 후보를 고를 때 내 채널의 점수가 매겨진 쇼츠(7일 이상 지난 것)를 함께 참고합니다. 잘된 쇼츠 5개, 부진한 쇼츠 3개(제목·길이·점수·지속률·구독 전환)와 패턴을 AI에게 주고, 점수 상위 3분의 1 쇼츠의 길이 범위(25~75백분위)를 계산해 후보마다 "내 채널 잘된 길이 / 더 짧음 / 더 김" 표시를 붙입니다. 길이 범위는 점수가 있는 쇼츠가 **6개 이상**일 때만 만들고, 3개 미만이면 채널 자료 자체를 쓰지 않습니다. 로그인이 안 됐거나 불러오기에 실패하면 채널 자료 없이 그대로 진행합니다. 이 자료는 길이와 스타일의 참고일 뿐, 영상에 없는 내용을 만들어 내지 않도록 지시해 두었습니다.
- 점수는 AI의 판단일 뿐 조회수를 보장하지 않습니다. 후보는 직접 확인하고 훅 자막은 고쳐서 쓰세요.
- 권리 확인과 데이터 전송 범위는 위 AI 자동 편집과 같습니다. 방송·타사 영상을 내려받거나 자동으로 모으는 기능은 없습니다.

#### 구간 미리 보기, 자막 편집

- **미리 보기**: 파일 경로로 넣은 영상은 서버가 그 구간만 360p로 빠르게 인코딩한 작은 복사본(`.data/previews/`, 하루 지나면 자동 삭제, 같은 구간은 다시 만들지 않음)을 보여 줍니다. 파일을 업로드한 경우에는 브라우저가 올린 파일을 직접 재생하며 구간 끝에서 멈춥니다(브라우저가 못 여는 형식은 파일 경로로 넣으면 됩니다). 원본 화면만 보여 주므로 훅·자막·세로 프레임은 만든 뒤 결과에서 확인하세요.
- **자막 편집**: 후보 카드에서 자막의 글자와 시작·끝 시간(이 쇼츠 시작을 0초로 한 초 단위)을 고치거나 줄을 추가·삭제하고 "처음 상태로"로 되돌릴 수 있습니다. 글자가 비었거나 시간이 맞지 않는 줄은 영상에 넣지 않고 빨간 칸으로 표시합니다. 수정한 내용 그대로 렌더링됩니다.

#### 롱폼 요약 구성

"롱폼 요약 구성도 만들기"를 켜면 같은 분석으로 가로 롱폼 한 편의 계획도 만듭니다(AI 호출 1회 추가, 원본의 절반 안팎·1~15분, 2분 미만 영상은 만들지 않음). 컷·자막·제목 3안·설명·해시태그에 더해 **챕터**를 제안하고, 다음 규칙으로 정리합니다.

- 챕터는 편집 후 영상의 시간으로 바꾸고, 잘려 나간 구간의 챕터는 다음 남은 구간의 시작으로 옮깁니다.
- YouTube가 설명의 시간표를 챕터로 인식하는 조건에 맞춥니다: 0:00부터 시작(처음 챕터가 10초 이상 뒤면 "오프닝"을 추가), 챕터 간격 10초 이상, **3개 미만이면 챕터를 넣지 않습니다**.
- 챕터 목록(`0:00 오프닝` 형식)은 설명 끝에 자동으로 붙고, 렌더링할 때 첫 챕터를 뺀 각 챕터에 4초짜리 제목 카드가 뜹니다(그 자리의 다른 자막은 카드에 자리를 내줍니다).
- AI 자동 편집(C)에서 롱폼 아이디어를 고른 경우에도 같은 챕터 처리가 적용됩니다.

#### AI 점수 검증

쇼츠를 만들면 그 후보의 AI 점수·이유·제목·구간이 `.data/clips.json`에 기록됩니다. 성과 추적 탭의 "AI 점수 검증"에서 올린 영상 목록(또는 주소 붙여넣기)으로 연결하면 비교합니다. 한 영상은 한 쇼츠에만 연결할 수 있습니다.

- 비교 대상은 영상의 **품질 점수**(내 쇼츠 안에서의 백분위, 업로드 7일 이후 매겨짐)입니다.
- 순위 상관이 0.5 이상이면 "맞는 편", 0.2~0.5 약하게 맞음, −0.2~0.2 관계 없음, −0.2 이하 반대로 맞음입니다. **점수가 매겨진 연결 영상이 5개 미만이면 판단하지 않습니다**(4개부터 AI 점수 상·하위 절반의 평균 실제 점수는 보여 줍니다). 표본이 적을 땐 우연히 좋게 나올 수 있습니다.
- 이 결과는 AI 점수를 믿어도 되는지 판단하는 근거일 뿐, 자동으로 점수 산정에 반영되지는 않습니다.

### 음성 인식의 처리 방식

Whisper는 무음 위에 없는 말을 지어내거나("MBC 뉴스 ○○○입니다" 같은 맺음말) 긴 침묵을 건너뛰면서 시간이 틀어지는 문제가 있어, **소리가 있는 구간만 잘라서 따로 인식**하고 결과를 원래 시간 위치에 되돌립니다. 지어낸 맺음말, 깨진 글자, 같은 줄 반복, 무음 위의 문장은 걸러 냅니다.

## 지표 정의

- **쇼츠**: 길이 3분 이하이면서 YouTube가 쇼츠로 취급하는 영상(아래 참고). 쇼츠 지속률이 100%를 넘는 것은 반복 재생이 포함되기 때문입니다.
- **품질 점수**: 같은 포맷 안의 백분위 가중 평균 — 조회 속도 20 · 지속률 30 · CTR 15 · 참여 15 · 구독 전환 20. 없는 지표는 제외하고 재정규화. 업로드 7일 미만은 미평가.
- **CVR**: 1천 조회당 신규 구독자. **CTA 반응**: `(댓글 + 공유) / 조회수`.
- **CTR**: YouTube Analytics API가 영상별 조회를 지원하지 않아 제외됩니다(Studio에서 확인).
- **성과 추적 기준선**: 내 기존 영상의 첫 N일(1·3·7·28) 누적 성적 분포. 새 영상과 같은 조건으로 비교합니다. **쇼츠와 롱폼은 따로** 계산하며, 한 형식의 기록이 5개 미만이면 그 기준선은 만들지 않고 해당 영상은 비교 없이 숫자만 표시합니다. 28일차는 천천히 쌓이는 롱폼을 위한 체크포인트입니다.
- **쇼츠/롱폼 구분**: 3분을 넘는 영상은 항상 롱폼입니다. 3분 이하 영상은 `youtube.com/shorts/<영상ID>`가 그대로 열리면 쇼츠, 일반 재생 페이지로 이동하면 쇼츠가 아닌 것으로 보고 롱폼으로 분류합니다(예: 3분 이하의 가로 영상). 공식 API가 아니라 **비공식 방법**이어서, 응답이 애매하거나 실패하면 판별하지 않고 길이 기준을 그대로 씁니다. 답은 영상별로 `.data/shorts.json`에 저장되며, 속도 제한을 피하려고 한 번에 최대 60개씩 하나씩 천천히 확인하므로 영상이 많은 채널은 데이터 새로고침을 몇 번 하면 모두 채워집니다. 내 채널과 연결한 영상에만 적용되고, 경쟁 채널·트렌드 영상은 길이 기준입니다.

## 테스트

```bash
npm test
```

네트워크나 실제 데이터 없이 도는 단위 테스트입니다(Node 내장 러너 + `tsx`, 약 15초). 점수 계산, 기준선 비교와 고정 결과, 관련성 필터(해시태그만 끼운 채널 판별), 타임스탬프·해시태그·영상 주소 파싱, 렌더 자막 줄바꿈, 소재 분류, 쇼츠·롱폼 렌더 레이아웃(실제 FFmpeg로 짧은 영상 생성), 롱폼 기준선 분리, AI 자동 편집(분석 로그 해석, 계획 정리, 구간 컷 렌더링, 음성 인식 결과 정리와 문장 경계 컷)을 다룹니다. 음성 인식 엔진 자체는 모델이 없어도 돌도록 가짜 엔진으로 테스트합니다. 쇼츠 후보 정리와 채널 성과 반영, AI 점수 검증(순위 상관·연결 규칙), 자막 편집 변환, 구간 미리 보기(실제 FFmpeg), 챕터 변환도 다룹니다. 렌더 테스트는 번들된 FFmpeg와 한글 폰트가 있을 때만 실행됩니다. 성과 추적 테스트는 `fetch`를 막아 두어서 API 호출이 생기면 실패합니다.

## 한계와 주의

- **방송·타사 영상을 내려받거나 자동으로 자르는 기능은 없습니다.** 소재 후보 찾기는 링크만 보여주며, 편집 자동화는 권리 확인에 체크한 영상에만 렌더링합니다. 권리 관계는 사용자 책임이며 권리자 정책을 직접 확인해야 합니다.
- 소재 후보의 "공식/팬 편집본" 표시는 제목·채널명으로 한 추정입니다.
- 인스타 릴스 성과 데이터는 수집하지 않습니다. 릴스는 성과 좋은 쇼츠의 재활용 아이디어로만 제안합니다.
- 패턴 인사이트는 상관관계이며 표본이 작으면 신뢰도가 낮습니다. 성과 추적은 영상 3개 미만이면 참고만 하세요.
- 토큰, 설정, 렌더 결과는 로컬 `.data/`에 저장됩니다(gitignore). 단일 사용자 로컬 실행용이며, 여러 사용자에게 서비스하려면 DB와 사용자별 세션이 필요합니다.
- 영상 편집에는 `ffmpeg-static`(프로젝트 내 설치)과 시스템 한글 폰트(맑은 고딕/나눔고딕)를 사용합니다.
